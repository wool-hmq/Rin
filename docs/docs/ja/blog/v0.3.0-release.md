# Rin v0.3.0-rc.1 プレリリース（公式アップストリーム）

**リリース日**: 2026年3月6日

`v0.3.0-rc.1` は、`v0.2.0` 以降に集中的に整理された最初のプレリリース版です。このリリース候補の目的は、長期間にわたるアーキテクチャ、パッケージング、認証、デプロイに関する作業を、明確な移行パスとともにレビューおよびアップグレード可能なバージョンにまとめることです。

## このプレリリースの焦点

### バックエンドランタイムの刷新

サーバーは旧来の Elysia ベースの経路から、Worker 向けのより軽量なランタイムへ移行し、さらに現在の Hono ベースのアプリ構成へと整理されました。

- ルートと依存関係はオンデマンドで読み込まれる
- ミドルウェア、エラーハンドリング、コンテキストの型付けがより明確になった
- サーバーは以前と同じフレームワークおよび依存関係のオーバーヘッドを抱えなくなった

### API と共有パッケージの整理

このバージョンラインは、アプリ間の共有境界も明確にします：

- `@rin/api`、`@rin/config`、`@rin/ui` がワークスペース構成の一部になった
- フロントエンドは Eden Treaty スタイルの呼び出しに依存せず、カスタムの型安全な API クライアントを使用する
- 開発、デプロイ、データベース、リリースのタスクは Rin CLI の下にまとめられた

### 認証と設定の更新

認証と設定の前提が大幅に変更されました：

- 認証は Authorization ヘッダーから Cookie に移行
- 以前の OAuth 依存はリポジトリ内実装に置き換えられた
- ユーザー名/パスワードログイン、`/login`、`/profile` が追加された
- `FRONTEND_URL` と `API_URL` に関する旧来のデプロイ前提が削除された

### データとパフォーマンスの作業

ランタイムの変更に加えて、このプレリリースにはいくつかの基盤的なアップグレードが含まれます：

- PV/UV 集計は HyperLogLog を使用するようになった
- CacheImpl は D1 または S3 のいずれかで永続化できる
- 設定、キャッシュ、キュー、Wrangler 関連のワークフローが複数のフォローアップ変更で tightened された

### コンテンツと編集の改善

`v0.2.0` 以降に追加された主要なユーザー向け機能も、このリリース候補に含まれます：

- Moments、検索、ピン留めフィード、隣接フィードナビゲーション
- 友だちリンクの並べ替え、申請フロー、通知
- AI 要約とカスタムモデルサポート
- Monaco エディタの改善
- Mermaid、KaTeX、コールアウト、アラート、コードコピー、画像ライトボックス、改善された Markdown 画像レンダリング

## 破壊的変更

### API クライアントの使用方法が変更

旧来の Eden Treaty スタイルのインターフェースは、もはやサポートされる経路ではありません。

旧：

```ts
const feeds = await client.feed.index.get({ query: { page: 1 } });
```

新：

```ts
const feeds = await client.feed.list({ page: 1 });
```

### 認証フローが変更

以前のヘッダーベースまたはモーダルベースのフローに合わせて認証をカスタマイズしていた場合は、その統合を再テストしてください：

- セッションのトランスポートは Cookie ベースになった
- ログインは専用ページに移動した
- プロフィール編集には独自のページができた

### デプロイ前提の変更

`FRONTEND_URL` と `API_URL` に関する旧来のデプロイモデルは削除されました。アップグレードは、現在のワークフロー、生成された Wrangler 設定、リポジトリレベルの変数に対して検証する必要があります。

## アップグレードのガイダンス

`v0.2.0` からアップグレードする場合は、少なくとも以下を確認してください：

1. カスタムのフロントエンド API 呼び出しを新しいクライアントサーフェスに更新する。
2. Cookie、専用ログインページ、コールバックフローを使用して認証動作を再テストする。
3. `CACHE_STORAGE_MODE` を `database` と `s3` のどちらにするか決定する。
4. GitHub OAuth 変数が `RIN_GITHUB_CLIENT_ID` と `RIN_GITHUB_CLIENT_SECRET` を使用していることを確認する。
5. 古いリリース習慣に依存せず、現在のビルドおよびデプロイフローを再実行する。

## このリリース候補に含まれる修正

このプレリリースには、既存の動作に影響する一連の修正も含まれます：

- RSS ルートとスケジュールタスクの問題
- CORS / OPTIONS の処理といくつかのクエリ解析バグ
- S3 の path-style 処理と画像プレースホルダーのメタデータ
- デプロイワークフローにおける Wrangler バージョンのずれ、キュー命名、環境変数の伝播の問題
- タイムラインのレンダリング、インデックスのスクロール、モバイル動作、キャッシュ初期化の問題

`v0.2.0` 以降に導入された機能のみを整理する修正は、ここでは意図的に一つずつ展開していません。

## 現在のステータス

`v0.3.0-rc.1` はまだプレリリースです。

フォークにカスタムの認証、デプロイ、API ラッパー、キャッシュ層の変更がある場合は、このラインを本番ベースラインとして扱う前に、自分の環境で検証してください。
